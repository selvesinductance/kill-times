## 1. コンセプト

20秒の連続モーショングラフィックが要所で「凍りつく」。止まった画面の中で、ただ一つ色と動きを残した物体の“形”（押せそう・引けそう・回せそう…）を読み取って正しく操作すると、止まっていた時間が弾けるように再始動する。

**コアループ:** 流れる（見る）→ 凍る（読む）→ 操作する（触る）→ 弾ける（爽快）→ 流れる …

設計原則

1. 文字で操作を指示しない。形・質感・微細な動き（アフォーダンスとシグニファイア）だけで伝える
2. 凍結中は世界の彩度を落として暗くし、操作対象だけを鮮やかに残す（スポットライト）
3. 操作が次の動きの「原因」になる（引いた玉がそのまま飛ぶ、切った縄が重りを落とす）
4. 成功の瞬間は「溜め → 解放」: ヒットストップ → 加速 → 衝撃波・粒子・揺れ・音
5. ワンカット構成: 区間のつなぎはカメラ移動と形の変形で行い、画面を切り替えない
6. ゲームオーバーなし。速さを競うタイムアタック。詰まったらヒントが段階的に出る
7. 操作する理由を映像で見せる。止まる前に「玉が向かう先（光・出口）」と「行く手を阻むもの」を見せ、仕掛けは場面の一部として最初からそこにある（止まる直前に部品だけ現れることはしない）

## 2. 20秒タイムライン

```
t(秒)  0        3.0        6.5        10.0       13.5       17.0     20.0
       |G0|--A---|G1|---B---|G2|---C---|G3|---D---|G4|---E---|G5|--F--| RESULT
       押す      引いて放す  滑らせる    切る        回す        連打
```

| 区間 | 時間 | モーション（要点） | 終端のゲート |
|---|---|---|---|
| タイトル | t=0 で凍結 | 暗い空間に、脈打つボタンだけがある | G0 押す（採点なし。音声の開始を兼ねる） |
| A 点火 | 0.0–3.0 | ボタンが光点に弾ける → 同心円と放射線 → 図形が飛来してY字のパチンコを組み上げる → 光点が図形に跳ね返りながらゴムに収まる | G1 引いて放す |
| B 飛翔 | 3.0–6.5 | 発射、カメラが追従 → リングのトンネルを疑似3Dで抜ける → 巨大な扉が滑り込んで行く手を塞ぐ | G2 滑らせる |
| C 落下 | 6.5–10.0 | 扉が左右に割れ光があふれる → 縦の空間へ落下、タイルがドミノ状に反転 → 縄で吊られた巨大な重りが現れる | G3 切る |
| D 衝撃 | 10.0–13.5 | 縄が弾けて重りが落下 → 床が破片になって砕ける → 下の機械室で歯車が噛み合い、回路線が描かれる → 光点が大ダイヤルの軸に収まる | G4 回す |
| E 充填 | 13.5–17.0 | 歯車が高速回転 → 回路を光が走り中心へ集束 → 光点が膨らみ殻をまとったコアになる → 殻にひびが1本入る | G5 連打 |
| F 解放 | 17.0–20.0 | 殻が爆散、衝撃波 → これまでの物体（ボタン・玉・つまみ・縄・ダイヤル）のシルエットが一瞬ずつ閃く → 渦を巻いてロゴに収束 → 「CLEAR」 | → リザルト |

- 各区間の終わりは演出側のイージング（ease-out）で減速させる。エンジンはゲート時刻ちょうどで時計を止めるだけ
- 各区間の始まりは強い ease-out（爆発的な出だし）で解放感を作る
- 区間内は正規化時間 u（0→1）で振り付けし、区間の長さは config だけで調整できるようにする

## 3. ゲート仕様（アフォーダンスと判定）

共通

- 長さ・距離は論理単位（安全領域 1000×1000）で書く
- 判定領域は見た目より広め。最小でも指1本分（論理 90 以上）
- 誤操作: 物体が「ぷるっ」と揺れて鈍い音（ミス +1。進行は妨げない）
- ヒントの段階: 0–3秒 物体自身の微動のみ → 3秒 輪郭の明滅で強調 → 6秒 半透明の“ゴーストの指”が操作を実演
- 反応時間 ＝ 凍結開始から成功まで（ヒットストップ中は含めない）
- 凍結前から押されていた指は無視する（前のゲートの操作が漏れないように）

| ゲート | 形（シグニファイア） | 成功条件（初期値） | 操作中の手応え | 成功の解放 |
|---|---|---|---|---|
| G0 押す | 盛り上がった円形ボタン（ハイライト＋落ち影）、ゆっくり脈動 | ボタン上で押下 | 押下で沈み込む | 衝撃波とともにボタンが光点に弾け、時間が動き出す |
| G1 引いて放す | Y字のパチンコとゴムに収まった光点。ゴムが微かに震え、玉が後ろへ沈んでは戻る | 玉をつかみ、発射方向の逆へ 140 以上引いて放す（向きは ±60° まで許容） | ゴムが伸びる、張力音のピッチ上昇、引くほど軽くズーム | 放した向きを最初の 0.2 秒だけ反映して発射、速度線 |
| G2 滑らせる | 扉にはめ込まれた溝と、滑り止めの筋が入ったつまみ。つまみが終端側へ「こつん」と小さく揺れる | 溝に沿って終端まで（進捗 95% 以上） | 溝が進んだ分だけ光で満ちる、10% ごとにカチッ。途中で離すとバネで戻る | 重い解錠音、扉が左右に割れる |
| G3 切る | 画面を斜めに横切る張った縄。中央がほつれて細く、微振動している | 縄を横切る速いスワイプ（指の軌跡が縄と交差し、速さ 1.0 単位/ms 以上） | 指の後ろに斬撃の軌跡。遅い横断は縄がたわむだけ | 閃光ライン、縄の両端が跳ね返り重りが落ちる |
| G4 回す | 外周にギザギザと持ち手のある大ダイヤル。周囲の歯車と噛み合い、±5° 揺れている | 中心まわりに時計回りで累積 360° | 歯車が連動、回転量に応じて光が溜まる、ラチェット音が高くなる。逆回しはガッと止まる | 機械が高速回転へ移行 |
| G5 連打 | ひびから光が漏れるコア。脈動がだんだん速くなる | コアを 8 回タップ（1.5 秒空くとひびが少し戻る） | タップごとにひびが増え、光量・揺れ・音程が上がる | 最大のヒットストップ → 白い閃光 → 爆散してフィナーレへ |

採点の基準タイム（PERFECT の上限）: G1 1.2秒 ／ G2 1.2秒 ／ G3 0.9秒 ／ G4 1.8秒 ／ G5 1.6秒。GREAT はその2倍、GOOD は4倍まで、それ以上は OK。

## 4. 爽快感（ジュース）の初期値

| 要素 | 初期値 | 備考 |
|---|---|---|
| ヒットストップ | 60ms（G1）→ 150ms（G5） | 後半ほど長く |
| 再始動の時間倍率 | 1.5 → 1.0 を 0.35 秒で | 解放の勢い |
| 画面揺れ | trauma 0.3〜1.0、減衰 1.5/秒 | 揺れ量 ＝ trauma² |
| 衝撃波リング | 半径 0→600、0.35 秒 ease-out | |
| パーティクル | 1回 40〜200 個、同時上限 600 | プールで再利用 |
| フラッシュ | 白 80ms → フェード | 全画面フラッシュは1秒に3回未満 |
| 成功音 | ゲートごとに音程が上がる和音 | 連続成功の高揚 |
| 凍結の見た目 | 彩度落とし＋暗転＋周辺減光、0.2 秒でフェードイン | 操作対象だけフルカラー |

`prefers-reduced-motion` のときは揺れとフラッシュを弱める。

### BGM（WebAudio でその場合成・音声ファイルなし）

| 場面 | 鳴り方 |
|---|---|
| テンポ | 120BPM の打ち込み系ループ（1拍 0.5秒）。動きの要所は 0.5秒の格子にそろえる |
| 盛り上がり | G0 後 ドラム → G1 後 +ベース → G2 後 +アルペジオ → G3 後 +コード → G4 後 +メロディ → G5 後（フィナーレ）全開＋大きな一撃、ロゴで終止和音 |
| 凍結した瞬間 | ローパスで音がこもって少し沈む → 心拍のような低い刻みだけが残る |
| 成功した瞬間 | 拍を待たず、その瞬間を小節の頭として全開で鳴り直す（シンバル＋フィルター全開） |
| リザルト | 静かなループ（ゆっくりしたコード）に切り替え |
| ミックス | 効果音を優先（大きな効果音の瞬間はBGMを一瞬下げる）。消音の切り替えは効果音と共通 |

## 5. 技術構成

- **成果物:** 外部ファイル・ライブラリなしの単一HTML（CSS/JS インライン）を公開ページにする。公開後は同じファイルで更新してURLを保つ（公開前にアーティファクトのデザイン指針を確認）
- **描画:** Canvas 2D、requestAnimationFrame、devicePixelRatio は最大 2
- **座標:** 原点中心の論理空間。1000×1000 の安全領域を画面の短辺に収め、背景は画面全体に広げる（縦持ちスマホと横長PCの両対応）
- **入力:** Pointer Events（マウス・タッチ・ペン共通）、`touch-action: none`、setPointerCapture。画面座標 → 論理座標 →（凍結時のカメラ逆行列）→ ワールド座標 で判定
- **時間:** マスター時計 t（0〜20秒）を `dt × timeScale` で進める。区間の描画は t の純関数にし、使う乱数もシード付き（同じ t なら同じ絵 ＝ 任意の時刻に飛べて検証しやすい）
- **凍結フレーム:** ゲート物体を除いた世界をオフスクリーンにキャッシュし、その上にゲートが物体を描く（二重描画を避け、負荷も下げる）
- **カメラ:** 位置・ズーム・回転を t の関数で持つ（DOMMatrix）
- **光彩:** shadowBlur は避け、事前描画したグロー用スプライトを 'lighter' 合成で重ねる
- **彩度落とし:** 'saturation' 合成で灰色を塗る（ctx.filter はブラウザ差があるので使わない）
- **音:** WebAudio でその場合成（ファイル不要）。G0 のタップで AudioContext を開始。ミュート切替あり
- **補助:** イージング関数群（expo / back / elastic など）とキーフレーム補助を core に持つ

状態遷移

```
TITLE(=G0で凍結) → PLAY → GATE(凍結・入力待ち) → BURST(ヒットストップ→加速) → PLAY … → FINALE → RESULT → (もう一度) → PLAY
```

ゲートの共通インターフェース（案）— 判定ロジックと見た目を分け、見た目だけ後から差し替える

```js
Gates.pull({
  at: 3.0,                       // 凍結する時刻
  /* 位置・方向・しきい値は config から */
  draw: null,                    // 本番の見た目（省略時はグレーボックス）
})
// 生成されるオブジェクト:
// enter()                 凍結開始: 状態初期化
// down(p) move(p) up(p)   入力（ワールド座標）
// update(dt)              微動・ヒント・進捗
// draw(g)                 凍結中の物体描画（フルカラー）
// done / reactionTime / misses
```

ステージの共通形（区間とその終端ゲートを1ファイルで持つ）

```js
Stages.push({
  id: 'A', from: 0.0, to: 3.0,
  camera(u) { /* {x, y, zoom, rot} */ },
  draw(g, u, opts) { /* 世界を描く。opts.omitGateObject は凍結キャッシュ用 */ },
  gate: Gates.pull({ at: 3.0 }),
});
```

デバッグ用 URL パラメータ

- `?debug` 時刻・状態・FPS・ゲート一覧、タイムラインのスクラブバー
- `?t=12.3` その時刻から開始
- `?auto` 各ゲートを 0.3 秒後に自動成功（通し検証用）
- テスト用の状態を `window.__fb` に公開（状態名、t、累計再生時間、各ゲートの結果）

## 7. 検証方法

- 環境: Python 版 Playwright と Chromium（/opt/pw-browsers）、Node 22 がある（起動確認は P1 で行う）
- 各フェーズの後: `node --check` で全 JS の構文確認 → `build.py` → `tools/check.py`
- `check.py` の確認項目
  1. `?auto` で RESULT まで到達する
  2. コンソールエラーが 0
  3. アニメーション部分の合計が 20 秒 ± 0.5
  4. 指定時刻（各ゲート直前・凍結中・直後）のスクショを、縦長 390×844 と横長 1280×720 で撮って目視
- 人の目での確認: 文字なしで操作が分かるか ／ 成功の瞬間が気持ちいいか ／ 詰まったときヒントが間に合うか

## 9b. 3D化の計画（2026-09-26 18:37 の要望）

要望: 3D空間にいる印象が欲しい。例: パチンコを引いた後、カメラがパチンコを横から見る位置へ回り込んでから玉が飛ぶ → 飛ばされた後、カメラが切れ目なく玉の後ろを追う角度になり、カメラも輪をくぐる → 扉を開けるとまた角度が変わる。

方針
- 世界を three.js（WebGL）の3D空間で描き直す。平面的な配色と太い形（モーショングラフィックの画風）は保ち、奥行き・遠近・カメラワークを加える
- 二層構成: 奥が3Dの世界（WebGL のキャンバス）、手前が2Dの重ね描き（操作対象・ヒント・集中線などの画面効果・UI）
- 凍結の瞬間、カメラは操作面を正面から見る位置に収まり、操作対象は2Dの重ね描きで「フラットな図形として浮かび上がる」（今の判定と描画をそのまま使う）。3D側の同じ物体は凍結中は隠し、成功後の状態（放した玉・開いた錠・切れた縄・回ったダイヤル・割れたコア）を3D側に引き継ぐ
- ゲート平面: 各ゲートに3D上の平面（原点・右方向・下方向・縮尺）を持たせ、画面座標 ↔ ゲート平面の2D座標を射影で変換する（入力と重ね描きの両方）
- カメラ: 区間ごとに u → 位置・注視点・画角・傾き の関数。区間の境目で連続させる。玉を追う場面は玉の3D軌道を少し遅れて追う
- 玉: 発光する3Dの球。軌道は物理（重力・空気抵抗・跳ね返り）
- 光と粒子: 加算合成のスプライトと THREE.Points（600個まで）。衝撃波は3Dのリング。集中線・フラッシュ・シャッターは2D
- 凍結の見た目: 3Dを一度テクスチャに描き、全画面の自作シェーダで彩度落としと周辺減光（外部の後処理ライブラリは使わない）
- 読み込み: three.js r128 を cdnjs から。読めない・WebGL が使えないときは今の2D版で動く（予備）
- 検証: ヘッドレス Chromium はソフトウェア描画（SwiftShader）で WebGL を動かす
- 移行中も最後まで遊べる状態を保つ: 3D化した区間だけ3Dで描き、まだの区間は今の2Dで描く
