# デザインと UI のこだわり（v2）

ゲーム制作（「五門の兵」「指スマ」）のなかで決めたことのうち、ほかの制作にも使えそうで、Claude に何も言わなければそうならないものをまとめた。必要なときに、必要な部分だけを使う。

- 書いてあるのは、ユーザーが自分で決めたことや直させたこと（Claude が仮に決めたことは入れていない）
- 「指示しないと」は、言われなければ Claude がやりがちなこと
- 「例」は実際の制作での具体例。（五門）は「五門の兵」、（指スマ）は指スマのゲーム
- ★ は2つ以上の制作で同じようなことを言われたもの。章も項目も、優先度の高い順に並べている
- 数値（角丸・太さ・透明度など）は、ここに書いた値を最初の案にして、変えやすい形で作る

---

```
多様性を生み出すため、最初ではなく必要な時に部分的にこのファイルを用いる。

リライトを要求されたとき、以下のことをしてください：
- 制作で要求されていてここに書いてない事項があったら、追記したり項目を増やしたりする。
- 「五門の兵」だけではなく、一般的な表現に
- 優先度順に並び替える。--同じようなことを言われたら優先度上昇、このファイルと食い違うことを言われた場合は優先度を下げるか消去。
- バージョンを上げる。
```

## 1. 説明と情報の量

- ★ **説明の文は書かない。** 見れば分かるものに、ことばを足さない。
  - ボタンに説明を付けない
  - 結果は一言だけにする（「はずれ」「当たり！」）。数は別の場所で見せる
  - 「これから入ります」のような予告も出さない（設定だけを置いておく）
  - 指示しないと：ボタンや画面に補足の説明を足す
  - 例（指スマ）：「立った親指は合計2本 → はずれ」「薄い数は、合計になり得ない数です」を消した
- ★ **同じ情報は1か所にだけ出す。**
  - 例（五門）：兵士の数は上の帯だけに出し、下にあった表示は消した。ボスの頭上は、数字ではなく HP バーにした（数字は帯にあるため）
  - 例（指スマ）：「1番手〜4番手」は列の見出しに一度だけ書き、ボタンの中では省いた。数値がボタンに書いてあるので、色の凡例は付けない
  - 指示しないと：ボタン一つ一つに見出しと同じ言葉を入れる。色の意味を示す帯（凡例）を付ける
- ★ **載せる情報は必要最小限にし、内訳より「読み」を出す。**
  - 例（五門）：兵士の数の下には「1億1000万」とだけ書き、兵種ごとの内訳は書かない
  - 例（指スマ）：情報欄は「ラウンド 1 ・ 宣言者 NPC2」だけ。対戦中の記録（ログ）は出さない
  - 指示しないと：情報欄にいろいろ載せる。ログを画面に出す
- **相手（NPC）の、不自然に見える行動には、理由をひとこと添える。** 説明を書かない決まりの例外。
  - 例（指スマ）：「はずれ（戦略のうち）」
- **ルールは「基本のルール」と「さらに今回は…（特別ルール）」に分けて、箇条書きにする。** 大事な点は太字にする。

## 2. 進め方

- ★ **まとまった依頼は、作る前に計画を見せ、確かめたいことを聞く。** 確かめたいことは選択肢の形で聞く。「開始」と言われてから始める。
  - 指示しないと：依頼を受けたらすぐ作り始める
- ★ **迷うところは、案を並べてから選んでもらう。** 図にしたり、何段階か試したりする。
  - 例（五門）：橋のたもとの案A〜D、字体の9案
  - 例（指スマ）：角丸や文字の太さを何段階か試した
- ★ **細かいところは Claude が決めてよい。ただし、あとで変えやすくし、報告する。**
  - 数値は、一か所で変えられる形（共通の変数など）にしておく
  - ユーザーの決定と Claude の仮の決定を分けて記録し、仮の決定は報告で知らせる
  - 指示しないと：数値を Claude が決めて、そのまま終わりにする
- ★ **頼まれた部分だけを変える。** 取り消した依頼の作業も残さない。
  - 例（指スマ）：「好きな色」だけを直す依頼では、色の見本の形も位置も変えない
  - 指示しないと：部分の修正のついでに、近くの部品もそろえて直す
- **見た目を変えたら、毎回スクリーンショットで見せる。** 大きさや幅など、数で決めにくいところは、Claude が見え方を確かめながら決めてよい。
- **品質は落とさない。** 軽くしたいときは、計算済みのデータを使うなど、別の方法をとる。
  - 指示しないと：軽くするために形や画質を落とす
- **公開中のページは、勝手に更新しない。** 遊んでいる人がいるかもしれないので、更新すると何が起きるか（遊んでいる途中の人が追い出されるか）を先に説明する。
  - 指示しないと：気づいた変更を、すぐ公開中のページに反映する

## 3. 主役と背景・飾り

- ★ **背景や飾りは主役より目立たせない。ただし消えてしまうほど薄くはしない。** 全体を見たときに、うっすら見える程度にする。
  - 例（五門）：低い草は地面の色に寄せる。寄せすぎて見えなくなったので、少し濃く戻した
  - 例（指スマ）：背景は全体をぼかし、主役の手だけをくっきり見せる。中央の数字も小さめ・透明度高めにして、手の邪魔をしない
  - 指示しないと：主役以外のものも大きく目立たせる
- **背景に情報を持たせない。**
  - 例（指スマ）：黒板は無地にする
  - 指示しないと：背景にも文字や模様を描き込む
- **形はリアルにし、部品の境目が見えないようにする。**
  - 例（指スマ）：リアルな形の、手袋をはめた手
  - 指示しないと：デフォルメした形にする。部品を組み合わせて、境目が見える形にする
- **なくてもよい土台は置かない。** 主役は空中に浮かせてよい。
  - 例（指スマ）：テーブル（ちゃぶ台）を置かず、手を空中に浮かせた
- **表面はなめらかにする。** 飾りのための凹凸（編み目・リブ）や縫い目は付けない。種類を素材で見分けるための質感は別（6章）。
- **飾りが多すぎたら、全体でまんべんなく減らす。**
  - 例（五門）：荒地の岩や枯れ木を、はじめの約3割まで減らした
- **主役のまわりを空けすぎない。** カメラと主役の間だけ空け、ほかは主役と重なってもよい。
  - 指示しないと：主役のまわりを丸く空けてしまう
- **広い画面でも、何もない地面が見えないようにする。** 数を増やさずに、植える範囲を遠くまで広げる手もある。
  - 例（五門）：タイトルの回るカメラに、地面がむき出しのところが映らないように、木を遠くまで植えた
- **自然のものは毎回ちがう形にし、遊びの公平さに関わるところは固定する。**
  - 例（五門）：岸・中州・半島の形はランダムだが、レーンが決まる線の位置と道の幅は変えない
- **アイコンは、ゲームの中の実物から作る。**
  - 例（五門）：開始画面のヘルメットは、3D のヘルメットを撮った絵（描いた絵ではない）

## 4. 画面の組み立てと形

- ★ **部品の形と大きさをそろえる。**
  - ボタンは正方形で、ほかのボタンと同じ高さにする。2文字ずつ2行の名前でもよい（例（五門）：「視点／変更」）
  - 角丸は3段階にする：窓・パネル 16px、ボタン 12px、小さい部品 6px（名札・札・情報欄・入力欄も含む）
  - 例外：色の見本（プリセット）は丸のまま。自分で選ぶ色だけ正方形にする（例（指スマ）：「好きな色 [■]」の順）
  - 指示しないと：部品ごとにばらばらの角丸にする（22・20・16・14・12・10・8px、名札は完全な丸）
- **端をそろえる。** 大きなボタンの右端を、上のボタン列の右端にそろえ、その下の一覧の幅もそこに合わせる。
- **一覧の説明は、書き出しを縦一列にそろえる。** 名前の列の幅を固定する。
- **上の HUD は、窓を並べずに1本の黒い帯にする。** 帯は高めにとって文字を大きくし、値は同じ大きさで横一列に並べる。
  - 指示しないと：カードや窓を並べる
- **遊びの中心になる数は、3D 空間の中に置く。**
  - 例（指スマ）：半透明の立体の数字を、中央に浮かべる
  - 指示しないと：画面に重ねて 2D で出す
- **左上は、一時停止ボタン1つにまとめる。** 中に「続ける・やりなおす・タイトルへ戻る・音声」を入れる。
  - 指示しないと：左上に「タイトルへ」「音声」などを並べる
- **補助のボタン列は、塗りのある窓に入れず、枠線だけにする。**
  - 例（指スマ）：「タイトルへ」ボタンと同じ見た目
- **横幅に余裕があれば2列や横並びに、狭ければ1列にする。** 画面の下に余裕があるときは、一覧を下にはりつける。
- **結果の画面は、結論のすぐ下に答え合わせを置く。** 選ばなかった選択肢の結果も見せる。ボタンは2つ並べて、画面の横幅いっぱいに広げる。
- **大事な一覧は、ボタンの奥にしまわない。** タイトルにコンパクトに並べ、関連する画面への入口はその行の中に置く。
  - 例（五門）：実績はタイトルに常に並べ、ゲート図鑑の入口は実績「ゲートマスター」の行に置く
- **まだ記録がないときは「ステージ - 」のように書く。** ダッシュの前後に空白を入れる。

## 5. 文字と字体

- ★ **字体は役割ごとに決め、数はしぼる。** 候補を並べて見比べてから選ぶ。
  - 本文：Noto Sans JP
  - 見出し・演出：角の丸い太字の M PLUS Rounded 1c
  - 例（五門）：開始演出の「ステージ1」は、9案から選んだ M PLUS Rounded 1c の極太
  - 指示しないと：1つの字体ですませる。または、個性の強い見出し用の字体（Dela Gothic One）や、本文にいろいろな字体（Zen Kaku Gothic New など）を使う
- **太さは 400・700・900 の3つにしぼる。** 読み込む太さも減らす。数値のそばの補助のラベル（「目安」など）は細く（400）して、数値を引き立てる。
  - 指示しないと：太さを細かく使い分ける（400・500・700・800・900）。補助のラベルも太字にする
- **数式や数字は、数字にくせのない字体にする。**
  - 例（五門）：UDデジタル教科書体があればそれ、なければ BIZ UDPGothic の太字。Klee One は数字にくせがあるのでやめた
- **日本語は、文節の切れ目でだけ改行する。** Safari を含む、どのブラウザでも効く方法にする。
  - 指示しないと：改行をブラウザ任せにして、言葉の途中で切れる
- **指数はちゃんと右上に置く。** 数式と札は少し大きめにする。
- **演出の大きな文字は、真っ白に縁取りをつける。**
- **名前は、誤解されないものに変えてよい。**
  - 例（五門）：ずっと回り続けると思われないよう「ループ」を「アンコール」に変えた。「1回きり」は「1ステージモード」、変数は x ではなく n

## 6. 色と素材

- ★ **いちばんのご褒美は虹色にする。** 虹色は継ぎ目なく、流れるように動かす。
  - 例（五門）：レアリティのいちばん上が虹
  - 例（指スマ）：全部達成すると、タイトルが虹色に流れて光る（ゲーミング色）
  - 指示しないと：達成しても見た目を変えない
- ★ **板・札・数字は半透明にする。** 板や札は素材の色の半透明にし、上に書く文字は縁取りごと半透明（50%）にする。
  - 例（指スマ）：中央の数字は半透明の立体
- **値の大小や段階は、色と明るさの両方で示す。** 明るさも値に合わせて変え、色の見分けが苦手な人にも順番が分かるようにする。
  - 例（指スマ）：値（難しさの目安）が小さいほど赤、大きいほど緑
  - 指示しないと：ボタンを全部同じ色にする
- **強調色は、大事な言葉だけに使う。**
  - 例（指スマ）：赤は「下げられない」にだけ使う
  - 指示しないと：強調色をタイトルの飾り全体に使う
- **みんなが知っている並びは、そのまま使う。**
  - 例（五門）：レアリティは白 → 緑 → 青 → 紫 → 金 → 虹。上の段階ほど強く光らせる
- **種類は「素材」で分ける。** 素材は、そのものが何をするかを連想させるものにし、色相・質感・形の印の3つを併用する。
  - 例（五門）：加減＝木、乗除＝青銅の歯車、符号＝鏡、累乗＝水晶、剰余・比較＝黒鉄、ランダム＝象牙、定数＝大理石
- **種類の色分けには、「良い・悪い」の意味を持たせない。** 赤＝危険、青・緑＝安全という連想が働く色分けは避ける。値の大小を示すときは、上の「値の大小や段階」に従う。
  - 指示しないと：種類を赤・青・緑などのはっきりした色で塗り分ける
- **参考の写真から取り入れるのは、形より色とつや。** 写真を渡したら「どこを取り入れるか」をまず確かめる。
  - 例（五門）：赤い鉄の橋の写真から、深い赤とつやだけを取る。赤は一度作ったあと、少し暗めに直した

## 7. 操作

- ★ **画面の中の物を、直接さわって操作できるようにする。**
  - 例（五門）：タップしたところへ寄せる。レーンに吸い付かせないので、迷わない
  - 例（指スマ）：自分の手を直接クリック・タップしても操作できる
  - 指示しないと：操作をパネルのボタンだけにする
- ★ **操作できるものや選んでいるものには、黄色・金色の印を付ける。**
  - 例（五門）：選んでいる金色の印は、押したボタンへすべって動かす
  - 例（指スマ）：操作できる 3D の物には、マウスを乗せると黄色い輪郭を付ける
  - 指示しないと：マウスを乗せてもカーソルが変わるだけ
- **横長の PC 画面では、操作する物のすぐ近くにもボタンを出す。** スマホでは出さない。
  - 例（指スマ）：手の下にボタンを出す
  - 指示しないと：操作パネルを画面の端に1つだけ置く
- **起こり得ない選択肢は薄く表示する。** ルール上は選べるなら、押せるままにする。
  - 指示しないと：押せなくするか、ふつうに表示する
- **矢印キーは、どの視点でも上下左右の全部を使える。**
  - 例（五門）：← と ↓ が同じ向き、→ と ↑ が同じ向き
- **待ち時間は長押しで早送りできるようにする。**

## 8. 動き・タイミング・カメラ

- ★ **派手な場面はたっぷり時間をかけ、決着の瞬間は間をあけない。** 結果は、公平に感じられるタイミングで出す。
  - 例（五門）：ブラックホールがふくらむ時間を、はじめの3倍にした。HP が0になったら、すぐ倒れ始める
  - 例（指スマ）：掛け声の「数」を言った瞬間に全員の手を出す（読み上げが終わるのを待たない）
  - 指示しないと：演出（読み上げ）が終わってから結果を出す
- **情報を示す物は揺らさない。** 止まっていて読みやすいことを優先する。
  - 例（指スマ）：中央の数字
  - 指示しないと：浮いている物をゆらゆら揺らして、生き生きさせる
- **ふだんは、全体を高いところから見下ろす視点にする。** 追う視点には、ボタンで切り替える。
- **見下ろすときは、文字が詰まらない向きに進ませる。**
  - 例（五門）：横長の画面では、右から左へ進ませる
- **大きな出来事では、見せたい視点へ強制的に切り替える。**
- **視点を切り替えるタイミングは、見せたいものが見え始めるところにする。**
  - 例（五門）：ボス戦の視点には、戦い始めではなく橋を渡りきったところで切り替える（ボスへ歩いてくる兵士が見える）
- **よく知られた動きを借りてよい。**
  - 例（五門）：ボスはマイクラのように、真横へ倒れて煙になる
- **HP バーは格闘ゲームのようにする。** 減った分を赤く残して、あとで縮める。増えたときは、枠を超えて伸びてよい。

## 9. 手がかりと知らせ

- **ヒントは半透明の黒い札にする。** 2行、中央ぞろえ。
- **ヒントは、必要なときだけ出す。**
  - 最初に操作するまで
  - 操作が10秒なかったとき
  - 使える機能を、まだ一度も使ったことがないとき
  - 操作したら消す
  - 指示しないと：ヒントを出しっぱなしにする
- **ヒントは邪魔にならないところに置く。** 矢印や主役に重ならず、少し離れたところ。
  - 例（五門）：道の外の芝生
- **知らせは決まった欄に、決まった瞬間に出す。** 知らせの音どうしが重ならないようにずらす。
  - 例（五門）：実績もアイテムも右上の同じ欄に出す。出すのは HP が0になった瞬間で、勝利の音とは重ならない
- **できないことは、説明より見た目と手ごたえで伝える。**
  - 例（五門）：横に動けない区間を、細い壁ではなく川にかかった橋にした。それでも横へ動かそうとすると欄干に当たり、音・小さなゆれ・欄干の光で返す
- **失敗を「やっちゃった」より「おっ」と感じさせる。** 失敗の見せ方を楽しくし、実績で歓迎する。
  - 例（五門）：マイナスの兵士、0除算のブラックホール、虚数のバグ
- **数が変わる様子を目に見せる。**
  - 例（五門）：兵士が実際に増える。桁が上がると大きな兵種に変わる

## 10. スマホと画面の大きさ

- **縦長の画面で、札が散らばって見づらくならないようにする。** 方法が複雑になりすぎるなら、札を小さくしてよい。
- **横長の広い画面でも、背景のはしが見えないようにする。** 3章の「何もない地面」と同じ。
- 画面の幅で変えることは、4章（列の数）と7章（操作する物の近くのボタン）にもある。

## 11. 音

- **環境音は控えめにする。** ふつうの大きさは、はじめに作った版の約1/3。足音も環境音に入れる。
  - 指示しないと：効果音と同じくらいの大きさにする
- **音量は「システム音・環境音・BGM」を別々に決められるようにする。** つまみは 0〜200 で、100 がふつう。
- **場所のある音は、近くにいるときだけ聞こえるようにする。** ただし見下ろし視点では、見ているところで聞くことにして、ふつうに聞こえるようにする。
- **一時停止中は、すべての音を止める。** 再開すると続きから鳴る。
- **画面の操作の音は、小さくやさしくする。**
  - 例（五門）：早送りを始めるときと終わるときの音は、なめらかに動く音ではなく、一段ずつ上がる・下がる、やわらかい短い音。1音ずつに、たたくような短い雑音を添える
- **雑音は、全体で控えめにする。**
  - 例（五門）：すべての雑音を、まとめて半分の大きさにした
- **音は、耳で聞いて詰める。** 試して戻すことも多い。
  - 例（五門）：1オクターブ下げる → 上の音と重ねる → 上の音だけに戻す。ピコピコした音を試して、やわらかい音に戻す
