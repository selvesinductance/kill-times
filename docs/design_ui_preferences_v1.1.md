# デザインと UI のこだわり

「五門の兵」を作るなかで決めたことのうち、ほかの制作にも使えそうで、Claude に何も言わなければそうならないものをまとめた。新しい制作の最初に、このファイルを Claude に渡して使う。

- 書いてあるのは、ユーザーが自分で決めたことや直させたこと（Claude が仮に決めたことは入れていない）
- 「指示しないと」は、言われなければ Claude がやりがちなこと
- 「例」は五門の兵での具体例

```
多様性を生み出すため、最初ではなく必要な時に部分的にこのファイルを用いる。

リライトを要求されたとき、以下のことをしてください：
- 制作で要求されていてここに書いてない事項があったら、追記したり項目を増やしたりする。
- 「五門の兵」だけではなく、一般的な表現に
- 優先度順に並び替える。--同じようなことを言われたら優先度上昇、このファイルと食い違うことを言われた場合は優先度を下げるか消去。
- バージョンを上げる。
```

## 1. 色と素材

- **色に「良い・悪い」の意味を持たせない。** 赤＝危険、青・緑＝安全という連想が働く色分けは避ける。
  - 指示しないと：種類を赤・青・緑などのはっきりした色で塗り分ける
- **種類は「素材」で分ける。** 素材は、そのものが何をするかを連想させるものにし、色相・質感・形の印の3つを併用する。
  - 例：加減＝木、乗除＝青銅の歯車、符号＝鏡、累乗＝水晶、剰余・比較＝黒鉄、ランダム＝象牙、定数＝大理石
- **みんなが知っている並びは、そのまま使う。** 上の決まりの例外にしてよい。
  - 例：レアリティは白 → 緑 → 青 → 紫 → 金 → 虹。上の段階ほど強く光らせる
- **参考の写真から取り入れるのは、形より色とつや。** 写真を渡したら「どこを取り入れるか」をまず確かめる。
  - 例：赤い鉄の橋の写真から、深い赤とつやだけを取る。赤は一度作ったあと、少し暗めに直した
- **虹色は継ぎ目なく、流れるように動かす。**
- **板や札は、素材の色の半透明にする。** 上に書く文字は、縁取りごと半透明（50%）にする。

## 2. 背景と飾り

- **飾りは主役より目立たせない。ただし消えてしまうほど薄くはしない。** 見下ろしたときにうっすら見える程度にする。
  - 例：低い草は地面の色に寄せる。寄せすぎて見えなくなったので、少し濃く戻した
- **飾りが多すぎたら、全体でまんべんなく減らす。**
  - 例：荒地の岩や枯れ木を、はじめの約3割まで減らした
- **主役のまわりを空けすぎない。** カメラと主役の間だけ空け、ほかは主役と重なってもよい。
  - 指示しないと：主役のまわりを丸く空けてしまう
- **広い画面でも、何もない地面が見えないようにする。** 数を増やさずに、植える範囲を遠くまで広げる手もある。
  - 例：タイトルの回るカメラに、地面がむき出しのところが映らないように、木を遠くまで植えた
- **自然のものは毎回ちがう形にし、遊びの公平さに関わるところは固定する。**
  - 例：岸・中州・半島の形はランダムだが、レーンが決まる線の位置と道の幅は変えない
- **アイコンは、ゲームの中の実物から作る。**
  - 例：開始画面のヘルメットは、3D のヘルメットを撮った絵（描いた絵ではない）

## 3. 画面の組み立て

- **上の HUD は、窓を並べずに1本の黒い帯にする。** 帯は高めにとって文字を大きくし、値は同じ大きさで横一列に並べる。
  - 指示しないと：カードや窓を並べる
- **ボタンは形と大きさをそろえる。** 正方形で、ほかのボタンと同じ高さにする。2文字ずつ2行の名前でもよい（「視点／変更」）。
- **端をそろえる。** 大きなボタンの右端を、上のボタン列の右端にそろえ、その下の一覧の幅もそこに合わせる。
- **一覧の説明は、書き出しを縦一列にそろえる。** 名前の列の幅を固定する。
- **横幅に余裕があれば2列や横並びに、狭ければ1列にする。** 画面の下に余裕があるときは、一覧を下にはりつける。
- **選んでいる印は、押したボタンへすべって動かす。**
  - 例：金色の印
- **説明の文は書かない。**
  - ボタンに説明を付けない
  - 結果の画面にも説明の文を出さない
  - 「これから入ります」のような予告も出さない（設定だけを置いておく）
  - 指示しないと：ボタンや画面に補足の説明を足す
- **同じ情報は1か所にだけ出す。**
  - 例：兵士の数は上の帯だけに出し、下にあった表示は消した。ボスの頭上は、数字ではなく HP バーにした（数字は帯にあるため）
- **内訳より「読み」を出す。**
  - 例：兵士の数の下には「1億1000万」とだけ書き、兵種ごとの内訳は書かない
- **結果の画面は、結論のすぐ下に答え合わせを置く。** 選ばなかった選択肢の結果も見せる。ボタンは2つ並べて、画面の横幅いっぱいに広げる。
- **大事な一覧は、ボタンの奥にしまわない。** タイトルにコンパクトに並べ、関連する画面への入口はその行の中に置く。
  - 例：実績はタイトルに常に並べ、ゲート図鑑の入口は実績「ゲートマスター」の行に置く
- **まだ記録がないときは「ステージ - 」と書く。** ダッシュの前後に空白を入れる。

## 4. 手がかりと知らせ

- **ヒントは半透明の黒い札にする。** 2行、中央ぞろえ。
- **ヒントは、必要なときだけ出す。**
  - 最初に操作するまで
  - 操作が10秒なかったとき
  - 使える機能を、まだ一度も使ったことがないとき
  - 操作したら消す
  - 指示しないと：ヒントを出しっぱなしにする
- **ヒントは邪魔にならないところに置く。** 道の外の芝生など、矢印や主役に重ならず、少し離れたところ。
- **知らせは決まった欄に、決まった瞬間に出す。** 知らせの音どうしが重ならないようにずらす。
  - 例：実績もアイテムも右上の同じ欄に出す。出すのは HP が0になった瞬間で、勝利の音とは重ならない
- **できないことは、説明より見た目と手ごたえで伝える。**
  - 例：横に動けない区間を、細い壁ではなく川にかかった橋にした。それでも横へ動かそうとすると欄干に当たり、音・小さなゆれ・欄干の光で返す
- **失敗を「やっちゃった」より「おっ」と感じさせる。** 失敗の見せ方を楽しくし、実績で歓迎する。
  - 例：マイナスの兵士、0除算のブラックホール、虚数のバグ
- **数が変わる様子を目に見せる。**
  - 例：兵士が実際に増える。桁が上がると大きな兵種に変わる

## 5. 操作

- **タップしたところへ寄せる。** レーンに吸い付かせないので、迷わない。
- **矢印キーは、どの視点でも上下左右の全部を使える。**
  - 例：← と ↓ が同じ向き、→ と ↑ が同じ向き
- **待ち時間は長押しで早送りできるようにする。**

## 6. カメラと動き

- **ふだんは、全体を高いところから見下ろす視点にする。** 追う視点には、ボタンで切り替える。
- **見下ろすときは、文字が詰まらない向きに進ませる。**
  - 例：横長の画面では、右から左へ進ませる
- **大きな出来事では、見せたい視点へ強制的に切り替える。**
- **視点を切り替えるタイミングは、見せたいものが見え始めるところにする。**
  - 例：ボス戦の視点には、戦い始めではなく橋を渡りきったところで切り替える（ボスへ歩いてくる兵士が見える）
- **派手な場面はたっぷり時間をかけ、決着の瞬間は間をあけない。**
  - 例：ブラックホールがふくらむ時間を、はじめの3倍にした。HP が0になったら、すぐ倒れ始める
- **よく知られた動きを借りてよい。**
  - 例：ボスはマイクラのように、真横へ倒れて煙になる
- **HP バーは格闘ゲームのようにする。** 減った分を赤く残して、あとで縮める。増えたときは、枠を超えて伸びてよい。

## 7. スマホと画面の大きさ

- **縦長の画面で、札が散らばって見づらくならないようにする。** 方法が複雑になりすぎるなら、札を小さくしてよい。
- **横長の広い画面でも、背景のはしが見えないようにする。** 2の「何もない地面」と同じ。

## 8. 文字

- **字体は役割ごとに決める。** 候補を並べて見比べてから選ぶ。
  - 例：ふつうの文字は Noto Sans JP。開始演出の「ステージ1」は、9案から選んだ M PLUS Rounded 1c の極太
  - 指示しないと：1つの字体ですませる
- **数式や数字は、数字にくせのない字体にする。**
  - 例：UDデジタル教科書体があればそれ、なければ BIZ UDPGothic の太字。Klee One は数字にくせがあるのでやめた
- **指数はちゃんと右上に置く。** 数式と札は少し大きめにする。
- **演出の大きな文字は、真っ白に縁取りをつける。**
- **名前は、誤解されないものに変えてよい。**
  - 例：ずっと回り続けると思われないよう「ループ」を「アンコール」に変えた。「1回きり」は「1ステージモード」、変数は x ではなく n

## 9. 音

- **環境音は控えめにする。** ふつうの大きさは、はじめに作った版の約1/3。足音も環境音に入れる。
  - 指示しないと：効果音と同じくらいの大きさにする
- **音量は「システム音・環境音・BGM」を別々に決められるようにする。** つまみは 0〜200 で、100 がふつう。
- **場所のある音は、近くにいるときだけ聞こえるようにする。** ただし見下ろし視点では、見ているところで聞くことにして、ふつうに聞こえるようにする。
- **一時停止中は、すべての音を止める。** 再開すると続きから鳴る。
- **画面の操作の音は、小さくやさしくする。**
  - 例：早送りを始めるときと終わるときの音は、なめらかに動く音ではなく、一段ずつ上がる・下がる、やわらかい短い音。1音ずつに、たたくような短い雑音を添える
- **雑音は、全体で控えめにする。**
  - 例：すべての雑音を、まとめて半分の大きさにした
- **音は、耳で聞いて詰める。** 試して戻すことも多い。
  - 例：1オクターブ下げる → 上の音と重ねる → 上の音だけに戻す。ピコピコした音を試して、やわらかい音に戻す

## 10. 進め方

- **見た目を変えたら、毎回スクリーンショットで見せる。** 大きさや幅など、数で決めにくいところは、Claude が見え方を確かめながら決めてよい。
- **迷うところは、案を図にして並べてから選んでもらう。**
  - 例：橋のたもとの案A〜D、字体の9案
- **細かいところは Claude が決めてよい。** ただしユーザーの決定と Claude の仮の決定を分けて記録し、仮の決定は報告で知らせる。
- **まとまった依頼は、まず順番を計画して見せる。** 「開始」と言われてから始める。
- **取り消した依頼の作業を残さない。**
